# 后台管理网页增强路线图

状态：实施中（截至 2026-07-24）

当前进度：P0-P2 的核心后台能力已落地，统一审计结果字段已覆盖主要高风险写操作；P3 的附件物理清理、存储探测、站内消息群发任务、孤儿附件任务和健康/任务状态入口已完成；P4 已补充概览指标细分、近 7 日趋势、命名筛选视图和批量治理流程。举报对象联动处置、敏感值加密、角色/分类群发、标签/字典引用检查、公告预览/发布记录和跨设备视图同步已补齐，并修复了附件索引在 MySQL `utf8mb4` 下超出 3072 字节限制导致安装迁移失败的问题。数据库自动备份、后台手动备份、保留策略、状态追踪、下载/删除权限、进程中断恢复和受控 MySQL 手动恢复已完成基础版本；Docker 默认备份目录已持久化到宿主机，Cron 计划已补充界面说明；后续聚焦跨实例任务队列持久化和加密配置密钥管理。

已完成的核心交付包括：管理路由权限矩阵和内容范围控制、敏感配置脱敏与白名单、Cookie/CSRF 防护、举报处置、评论管理、用户禁言、话题置顶和问答采纳、操作日志页面、标签/字典页面、收藏只读查询以及投票相关页面。

## 1. 目标

逐步将后台管理网页建设为主要运营入口，使管理员能够在图形化界面完成绝大多数内容治理、用户治理、权限治理和站点运营工作。

后台不应只是数据库 CRUD 页面，还需要覆盖以下闭环：

- 发现问题：统计、待办、搜索、筛选和举报定位。
- 处理问题：删除内容、删除评论、封禁用户、恢复内容和处理问答状态。
- 追踪结果：操作日志、处理人、处理时间、处理原因和相关对象。
- 控制风险：权限、内容范围、敏感配置、二次确认和批量操作保护。

## 2. 当前基线

### 2.1 已有网页能力

当前后台已有以下页面：

- 工作台概览。
- 话题列表和推荐、删除、恢复、问答解决状态操作。
- 分类管理。
- 友情链接管理。
- 用户列表、创建、编辑、角色分配和重置密码。
- 用户举报列表、举报详情和标记处理/忽略。
- 角色和角色权限管理。
- 站点、内容、登录、上传、通知、页面、脚本等系统设置。
- 标签、字典类型和字典项管理。
- 收藏、投票、投票选项和投票记录的只读查询。
- 操作日志列表和详情查询。
- 附件查询、详情、物理删除、异步孤儿附件清理和存储探测。
- 单用户站内消息创建、编辑、查询和软删除，以及面向全站、角色或分类范围的群发草稿、预览、发送记录和失败重试。
- 数据库、存储配置、搜索和 Sitemap 状态查看，以及搜索重建和 Sitemap 任务入口。

前端已经有通用数据管理组件，支持分页、筛选、详情、表单、权限控制、树形选择、排序、行操作和当前页批量选择。新增标准管理页面应优先复用该组件；举报、审核处置和内容工作台等复杂流程使用专用页面。

### 2.2 已有后端能力与网页入口现状

附件、站内消息和健康/任务状态已经提供网页入口，主要完整流程已补齐；剩余工作主要是跨实例持久化任务队列等增强能力：

- 附件对象存储的物理删除、统一 uploader 接口和真实连通性探测已完成。
- 站内消息面向角色或分类范围的群发、草稿预览、发送记录和失败重试已完成。
- 孤儿附件清理任务、任务进度/失败状态和缓存状态管理已完成；跨实例持久化任务队列仍可继续增强。

数据库迁移和执行 Shell 等基础设施操作继续使用受控的部署或 CLI 流程，不作为普通网页按钮开放。数据库自动备份、后台手动备份和受控 MySQL 手动恢复必须使用独立权限、二次确认、恢复前安全备份、备份有效性校验和完整操作审计。

## 3. P0：扩展前置条件（大部分完成）

这些事项完成前，不扩大高权限管理功能。

### 3.1 权限矩阵和接口一致性（已完成核心项）

- 为每个已注册的 `/api/admin` 路由建立方法、路径、所需权限和内容范围矩阵。
- 增加自动测试，确保每个管理路由都有明确权限规则，避免出现“自定义管理员不可用、站长因 owner bypass 可以使用”的隐式行为。
- 为查看、创建、编辑、删除、排序、封禁、重置密码、处理举报、执行后台任务分别定义权限。
- 对置顶、采纳答案、删除评论等已有处理器补齐权限和前端入口。
- 明确管理员角色的分类范围：无分类授权时应显示明确提示，而不是返回空列表。
- 所有前端隐藏按钮都必须同时由后端权限保护。

### 3.2 敏感配置保护（核心完成）

敏感配置的响应脱敏、可写 key 白名单、加密存储和清除语义均已落地，以下记录当前能力和后续增强方向：

- 已完成：管理配置响应只返回脱敏值或是否已配置状态。
- 已完成：提交空白敏感字段表示保持原值，明确的清除操作需要二次确认。
- 已完成：后端对可写配置 key 使用白名单，不接受任意 key。
- 已完成：普通设置查看/编辑与敏感配置更新使用不同权限。
- 已完成基础版本：敏感值使用 AES-GCM 加密存储，支持 `BBSGO_CONFIG_ENCRYPTION_KEY` 或 `security.encryptionKey`，旧明文可兼容读取。
- 已完成：仅提交空白敏感字段时保留原值，显式 `clearSensitive` 才会清除；配置列表和详情不会返回密文。
- 保存敏感配置、登录配置和上传配置时写入审计日志。

### 3.3 Cookie、CSRF 和高风险操作（核心完成）

- 为登录 Cookie 明确设置 `Secure`、`HttpOnly` 和合适的 `SameSite` 策略。
- 为基于 Cookie 的后台写操作增加 CSRF 防护，或统一要求不可被跨站自动携带的管理令牌。
- 删除、封禁、重置密码、修改权限、保存脚本等操作必须二次确认。
- 批量操作显示影响数量和对象范围，默认不提供不可逆的批量删除。
- 脚本注入、外部链接、上传提供商配置需要 URL、大小、协议和内容校验。

### 3.4 统一审计（主要完成，后续不扩展全量覆盖）

- 统一记录操作人、操作类型、对象类型、对象 ID、请求 IP、User-Agent、时间、结果和描述。
- 覆盖角色、权限、设置、分类、链接、话题、评论、用户、举报、脚本和后台任务。
- 已补齐角色创建/编辑/删除/排序、角色权限修改、分类创建/编辑/删除/排序、友情链接创建/编辑/删除/排序的成功操作审计；批量操作记录对象数量，权限变更不记录权限明细。
- 已补齐审计结果统一归一化和失败记录辅助方法，并接入公告发布、群发任务、附件删除、举报处置和筛选视图保存等高风险流程。
- 审计日志不可由普通管理员修改或删除。
- 日志详情中隐藏密码、Token、Client Secret、Access Key 等敏感值。
- 当前范围决策：保留主要高风险流程的审计能力，不再安排全量历史 CRUD 的请求级审计补齐和完整前后变化摘要建设。

## 9. 验收标准

### 功能

- 管理员可以从举报详情完成帖子、评论和用户的主要处置动作。
- 管理员可以在用户列表完成禁言和解除禁言。
- 管理员可以在话题后台完成推荐、置顶、删除、恢复和问答状态处置。
- 角色权限和分类内容范围在列表、详情和写操作中保持一致。
- 操作日志能追溯主要高风险管理动作，未覆盖项有明确的补齐计划。
- 标准运营模块不需要直接操作数据库。
- 数据库自动备份能够按计划执行，展示最近成功/失败状态、保留策略和失败原因。
- 管理员可以在独立权限和二次确认保护下手动备份；手动恢复必须先创建安全备份并通过备份来源、格式、完整性和兼容性校验。

### 安全

- 非授权角色访问管理接口返回 403。
- 未配置对应分类范围的管理员不会意外看到全站内容。
- 前端响应和日志中不存在明文密码、Token 或第三方密钥。
- 跨站请求不能触发后台写操作。
- 删除、封禁、权限修改和敏感配置保存都有确认和审计。
- 备份、恢复、下载和删除备份都有独立权限、二次确认和操作审计；网页不提供任意 SQL 或 Shell 执行。

### 测试
