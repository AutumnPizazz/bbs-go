# 后台管理网页增强路线图

状态：实施中（截至 2026-07-23）

当前进度：P0-P2 的核心后台能力已落地，统一审计覆盖已继续补齐角色、角色权限、分类、友情链接、话题处置和后台任务；P3 已启动并完成附件查询/软删除/孤儿清理、受控站内消息和健康/任务状态入口；P4 已补充概览指标、近 7 日趋势、列表筛选保存和批量治理基础流程。整体仍有举报对象联动处置、跨页批量工作流、敏感值加密、真正的角色/分类群发流程和部分引用检查缺口。

已完成的核心交付包括：管理路由权限矩阵和内容范围控制、敏感配置脱敏与白名单、Cookie/CSRF 防护、举报处置、评论管理、用户禁言、话题置顶和问答采纳、操作日志页面、标签/字典页面、收藏只读查询以及投票相关页面。

## 1. 目标

逐步将后台管理网页建设为主要运营入口，使管理员能够在图形化界面完成绝大多数内容治理、用户治理、权限治理和站点运营工作。

后台不应只是数据库 CRUD 页面，还需要覆盖以下闭环：

- 发现问题：统计、待办、搜索、筛选和举报定位。
- 处理问题：删除内容、删除评论、封禁用户、恢复内容和处理问答状态。
- 追踪结果：操作日志、处理人、处理时间、处理原因和相关对象。
- 控制风险：权限、内容范围、敏感配置、二次确认和批量操作保护。

## 2. 当前基线

### 2.1 已有网页能力

当前后台已有以下页面：

- 工作台概览。
- 话题列表和推荐、删除、恢复、问答解决状态操作。
- 分类管理。
- 友情链接管理。
- 用户列表、创建、编辑、角色分配和重置密码。
- 用户举报列表、举报详情和标记处理/忽略。
- 角色和角色权限管理。
- 站点、内容、登录、上传、通知、页面、脚本等系统设置。
- 标签、字典类型和字典项管理。
- 收藏、投票、投票选项和投票记录的只读查询。
- 操作日志列表和详情查询。
- 附件查询、详情、软删除和孤儿附件清理。
- 单用户站内消息创建、编辑、查询和软删除。
- 数据库、存储配置、搜索和 Sitemap 状态查看，以及搜索重建和 Sitemap 任务入口。

前端已经有通用数据管理组件，支持分页、筛选、详情、表单、权限控制、树形选择、排序、行操作和当前页批量选择。新增标准管理页面应优先复用该组件；举报、审核处置和内容工作台等复杂流程使用专用页面。

### 2.2 已有后端能力但网页入口或完整流程仍待补齐

附件、站内消息和健康/任务状态已经提供基础网页入口，但以下完整能力仍需继续设计和实现：

- 附件对象存储的物理删除、统一 uploader 接口和真实连通性探测。
- 站内消息面向角色或分类范围的群发、草稿预览、发送记录和失败重试。
- 孤儿附件清理任务、统一后台任务队列、进度/失败/重试流程以及缓存状态管理。

迁移、备份、恢复、执行 Shell 等基础设施操作暂时不作为普通网页按钮开放，继续使用受控的部署或 CLI 流程，后续会作为普通网页按钮开放。

## 3. P0：扩展前置条件（大部分完成）

这些事项完成前，不扩大高权限管理功能。

### 3.1 权限矩阵和接口一致性（已完成核心项）

- 为每个已注册的 `/api/admin` 路由建立方法、路径、所需权限和内容范围矩阵。
- 增加自动测试，确保每个管理路由都有明确权限规则，避免出现“自定义管理员不可用、站长因 owner bypass 可以使用”的隐式行为。
- 为查看、创建、编辑、删除、排序、封禁、重置密码、处理举报、执行后台任务分别定义权限。
- 对置顶、采纳答案、删除评论等已有处理器补齐权限和前端入口。
- 明确管理员角色的分类范围：无分类授权时应显示明确提示，而不是返回空列表。
- 所有前端隐藏按钮都必须同时由后端权限保护。

### 3.2 敏感配置保护（核心完成）

当前管理配置响应包含 OAuth、OSS、COS 和 S3 的密钥字段，保存接口也接受任意配置 key。需要改为：

- 管理配置响应只返回脱敏值或是否已配置状态。
- 提交空白敏感字段表示保持原值，明确的清除操作需要二次确认。
- 后端对可写配置 key 使用白名单，不接受任意 key。
- 将普通设置查看/编辑与敏感配置更新拆分权限。
- 评估敏感值加密存储或使用环境变量/外部密钥管理服务。
- 保存敏感配置、登录配置和上传配置时写入审计日志。

### 3.3 Cookie、CSRF 和高风险操作（核心完成）

- 为登录 Cookie 明确设置 `Secure`、`HttpOnly` 和合适的 `SameSite` 策略。
- 为基于 Cookie 的后台写操作增加 CSRF 防护，或统一要求不可被跨站自动携带的管理令牌。
- 删除、封禁、重置密码、修改权限、保存脚本等操作必须二次确认。
- 批量操作显示影响数量和对象范围，默认不提供不可逆的批量删除。
- 脚本注入、外部链接、上传提供商配置需要 URL、大小、协议和内容校验。

### 3.4 统一审计（部分完成）

- 统一记录操作人、操作类型、对象类型、对象 ID、请求 IP、User-Agent、时间、结果和描述。
- 覆盖角色、权限、设置、分类、链接、话题、评论、用户、举报、脚本和后台任务。
- 已补齐角色创建/编辑/删除/排序、角色权限修改、分类创建/编辑/删除/排序、友情链接创建/编辑/删除/排序的成功操作审计；批量操作记录对象数量，权限变更不记录权限明细。
- 审计日志不可由普通管理员修改或删除。
- 日志详情中隐藏密码、Token、Client Secret、Access Key 等敏感值。

## 4. P1：先完成内容治理闭环（核心闭环完成）

### 4.1 举报工作台（主要完成）

将举报页从“工单状态管理”升级为“举报处置工作台”：

- 按待处理、已处理、已忽略、类型、时间、对象 ID、处理人筛选。
- 展示举报原因、举报人、被举报对象、上下文内容和历史举报数量。
- 帖子/问答举报支持查看、删除和必要时恢复。
- 评论举报支持定位到所属帖子、查看上下文、删除评论。
- 用户举报支持查看用户资料、禁言、解除禁言和查看历史举报。
- 处置动作和举报状态更新应保持一致，并记录操作日志。
- 待完善：支持“仅处理当前举报”和“处理对象并关联其他举报”两种模式，避免重复处理。

### 4.2 评论管理（已完成）

新增后台评论接口和页面：

### 4.3 用户处置（已完成核心项）

### 4.4 话题和问答处置（已完成核心项）

## 8. 推荐实施顺序

1. 建立管理路由/权限矩阵，补齐接口权限测试。
2. 处理敏感配置、Cookie、CSRF 和统一审计。
3. 完成举报工作台、评论管理、用户禁言和话题置顶/问答处置。
4. 上线操作日志、标签、字典和投票只读分析。
5. 完善附件、消息、健康检查和后台任务的缺失工作流。
6. 完善跨页批量操作、失败重试、统计报表和个性化工作台。

每个阶段都应先完成后端接口、权限和审计，再接入前端页面，避免出现只有站长可用或只有前端隐藏的半成品功能。

## 9. 验收标准

### 功能

- 管理员可以从举报详情完成帖子、评论和用户的主要处置动作。
- 管理员可以在用户列表完成禁言和解除禁言。
- 管理员可以在话题后台完成推荐、置顶、删除、恢复和问答状态处置。
- 角色权限和分类内容范围在列表、详情和写操作中保持一致。
- 操作日志能追溯所有高风险管理动作。
- 标准运营模块不需要直接操作数据库。

### 安全

- 非授权角色访问管理接口返回 403。
- 未配置对应分类范围的管理员不会意外看到全站内容。
- 前端响应和日志中不存在明文密码、Token 或第三方密钥。
- 跨站请求不能触发后台写操作。
- 删除、封禁、权限修改和敏感配置保存都有确认和审计。

### 测试

- Go 测试覆盖权限矩阵、管理处理器、内容范围和高风险操作。
- 前端通过 `pnpm lint`、`pnpm typecheck` 和生产构建。
- 运行相关 `web/scripts/test-dashboard-*.mjs` 回归脚本。
- 完整 Go 测试前先生成 `web/build/spa`，推荐使用 `make web-build-spa` 后再运行 `make test`。
- 对 owner、全站管理员、分类管理员、只读管理员和无权限用户分别验证关键流程。
