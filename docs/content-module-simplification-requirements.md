# 内容模块精简需求

## 1. 背景与目标

当前项目同时存在帖子、文章、动态和问答等内容概念，但文章在数据层已经复用帖子模型，动态也复用帖子发布链路。多套入口、格式和管理页面增加了产品理解及维护成本。

本次改造将内容体系收敛为两类：

- 帖子：用于普通讨论和内容发布。
- 问答：保留提问、回答、采纳和解决状态等问答能力。

同时取消发布前内容审核和违禁词机制，内容治理统一采用用户举报与管理员事后处置。

项目当前处于开发阶段，不要求兼容既有文章、动态或待审核数据，也不要求提供数据迁移、旧接口兼容或旧地址重定向。

## 2. 核心需求

### 2.1 移除文章模块

系统不再存在“文章”这一独立内容概念。

- 删除文章模块开关及相关系统配置。
- 删除文章发布、编辑、列表、标签列表、个人文章列表和后台文章管理入口。
- 删除 `/articles` 等文章专属路由和文章专属 API 使用方式。
- 删除 `TopicFormat`、`post/article` 格式判断及所有 `format` 查询条件。
- 删除文章专属权限、统计指标、搜索分类、站点导航项和多语言文案。
- 删除文章专属字段及交互，包括摘要、封面和来源链接。
- 普通帖子继续使用现有帖子发布、列表、详情、搜索和后台管理链路。

文章能力不合并成一种“高级帖子模式”。如未来确实需要封面、摘要等能力，应作为独立的新需求，为所有帖子重新设计。

### 2.2 移除动态模块

删除由 `TopicTypeTweet` 表示的短动态内容类型。

- 删除动态模块开关及相关系统配置。
- 删除发布动态的入口、表单模式、校验和接口分支。
- 删除动态专属列表、展示样式、标题生成逻辑、通知文案、统计和多语言文案。
- 删除 `TopicTypeTweet` 常量及所有针对该类型的条件分支。
- 内容类型只保留普通帖子和问答。

“删除动态”不代表删除关注关系或关注内容流。若关注信息流能够正常展示普通帖子和问答，则予以保留；其中仅服务于动态的代码应删除。

### 2.3 删除发布前审核

所有合法请求在发布成功后立即可见，不再进入待审核状态。

- 删除 `StatusReview` 内容状态及其发布逻辑。
- 删除内容审核接口、审核权限、审核按钮和待审核筛选。
- 删除待审核数量、后台待办项及前台“审核中”提示。
- 删除文章审核配置 `articlePending` 及相关配置 DTO、缓存读取和设置界面。
- 普通帖子和问答只保留正常与删除等实际使用的内容状态。

本项仅删除“内容发布审核”。举报记录自身仍需有待处理、已处理、已忽略等工单状态。

### 2.4 删除违禁词机制

系统不再扫描、拦截或标记标题和正文中的违禁词。

- 删除违禁词模型、数据表及数据库注册。
- 删除违禁词服务、仓储、匹配逻辑和缓存。
- 删除后台违禁词管理页面、接口、路由和权限。
- 删除发布流程中的违禁词检查及相关日志。
- 删除违禁词相关多语言文案、测试和配置。

不保留“命中后拒绝发布”或“命中后转审核”的替代逻辑。

### 2.5 保留举报与事后治理

用户可继续举报帖子、问答、评论和用户，管理员通过举报后台完成处置。

- 文章和动态不再作为举报数据类型。
- 帖子与问答统一使用 `topic` 举报类型。
- 保留举报原因、举报人、被举报对象和处理状态。
- 将举报领域中的 `audit` 命名和界面文案调整为“处理”，避免与已删除的内容审核混淆。
- 保留管理员删除内容、删除评论和封禁用户等处置能力。
- 保留推荐、置顶及问答解决状态等与发布审核无关的管理能力。

## 3. 目标内容模型

改造后的主题内容只包含以下类型：

| 类型 | 用途 | 主要能力 |
| --- | --- | --- |
| 普通帖子 | 社区讨论及一般内容发布 | 标题、正文、分类、标签、附件、投票、回复可见、评论、点赞、收藏 |
| 问答 | 提问及回答 | 标题、正文、问答分类、回答、采纳、已解决/未解决状态、评论、点赞、收藏 |

问答继续使用现有主题模型和评论体系，不拆分为独立数据表。

## 4. 实施范围

实施时应完整清理以下层面，避免只隐藏前端入口：

- 数据模型、常量和数据库初始化。
- 服务、仓储、缓存和搜索索引。
- API 路由、请求参数和响应字段。
- 前台路由、组件、导航和用户主页。
- 后台页面、权限、统计和设置。
- 消息通知、站点地图及 SEO 元数据。
- 中英文文案、测试、示例配置和文档。

数据库可直接按精简后的模型重新初始化。无需为已删除的表、字段、枚举值和配置项编写生产数据迁移。

## 5. 非目标

- 不迁移或转换已有文章、动态及待审核内容。
- 不保留旧文章/动态 URL、接口或请求参数的兼容层。
- 不新增自动内容审核、敏感词替代方案或第三方风控服务。
- 不删除评论、点赞、收藏、关注、举报、推荐、置顶或用户封禁能力。
- 不在本次改造中重新设计帖子编辑器或新增封面、摘要能力。

## 6. 验收标准

1. 前台和后台不再出现文章、动态、违禁词或内容审核相关入口与文案。
2. API 不再接受 `format=article` 或动态类型，响应中不再包含仅为这些模块服务的字段。
3. 用户只能发布普通帖子或问答，发布成功后内容立即可见。
4. 普通帖子和问答的发布、编辑、列表、详情、搜索、评论、点赞、收藏及举报流程正常。
5. 普通帖子仍可使用附件、投票和回复可见；问答的回答、采纳和解决状态正常。
6. 举报后台可以查看举报目标，并将举报标记为已处理或已忽略；管理员能够据此删除内容、删除评论或封禁用户。
7. 新建数据库后不存在文章、动态、违禁词及发布审核专属表、字段、权限和配置项。
8. 全仓库不存在仍参与运行的文章格式、动态类型、违禁词检查或 `StatusReview` 分支。
9. 后端测试、前端类型检查、构建和相关端到端流程全部通过。

## 7. 建议实施顺序

1. 收敛后端主题模型和发布流程，仅保留普通帖子与问答。
2. 删除文章、动态、审核和违禁词相关 API、权限及配置。
3. 删除对应前后台页面、组件、导航和文案。
4. 调整搜索、举报、通知、统计与站点地图等横向能力。
5. 重新初始化数据库并补齐回归测试。
6. 全仓库搜索遗留标识并完成最终清理。
